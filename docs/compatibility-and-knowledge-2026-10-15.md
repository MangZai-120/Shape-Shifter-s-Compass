# Compass 1.0.1 核对记录

## 范围与来源

目标是同一个客户端 JAR 同时读取 SSC 1.9.2 与 1.10.x，知识资料跟随实际加载版本。真实发行包接口核对覆盖 SSC 1.9.2、1.10.0、Apoli 2.9.0、2.9.2 和 CCA 5.2.2。未声称验证尚未提供的所有后续 1.10 小版本。

SSCA 知识来源分别为本地 `1036d748`（8.0.0-magic-dev.3-ssc-1.9.2）与 `c11c69ec`（8.0.0-magic-dev.4）代码和资源。详细 Wiki 使用 [LynxCatTheThird/SSC-wiki](https://github.com/LynxCatTheThird/SSC-wiki/tree/f279b358aaf759bab314868f18ecafaf9ed22182/docs/ssc) 的 14 页 SSC 文档。在线补查了 [SSC MC百科](https://www.mcmod.cn/class/20760.html) 与 [SSCA MC百科](https://www.mcmod.cn/class/24327.html) 的模组主页面；部分物品详情页无法由网页工具读取，未将其冒充为已核实详情。

## 确认的问题与修复

| 项目 | 证据 | 结果 |
|---|---|---|
| SSC 1.9.2 形态读取失败 | 发行包无 `player_form.utils.FormUtils`；实际组件是 `ability.RegPlayerFormComponent.PLAYER_FORM` → `getCurrentForm()` → 公开 `FormID` | 自动选择旧组件路径，同时保留新版 `FormUtils/getFormID` 路径；不缓存玩家的旧形态 |
| CCA 反射访问风险 | 组件键可能由不可公开的生成实现类提供 | 通过公共 `ComponentKey` API 调用 |
| 资源单位与空结果混淆 | 原工具把所有资源标为 tick，把读取异常和无资源合并 | 分开显示资源点/原始值与真实冷却；失败单独报告，并记录一次诊断日志 |
| 原生法力缺失 | SSC `ManaComponent` 独立于 Apoli `VariableIntPower` | 增加原生法力、上限与类型读取 |
| 旧版指令错误 | 1.9.2 命令树为 `set_custom_form`，1.10.0 为 `set_dynamic_form`，后者另有子形态入口 | 两套资料精确标记安装版本 |
| 旧知识混入新环境 | 核心与百科镜像来自 8 月 beta.2/1.10.x；外部 Wiki 每次构建无版本复制 | 排除旧镜像，改为可复现的分版本固定快照 |
| 搜索误匹配 | 旧搜索按单个汉字加分，容易召回无关条目 | 词组/单词/中文双字检索，稳定排序，限定篇幅，每条带来源和版本 |
| 魔法书与形态资源混淆 | `set_mana` 实现未写书 NBT，不覆盖所有计数器 | 更正恢复法力说明，补齐经验与CD命令、旧别名、渐进扣蓝、净化打断 |
| 空外环误称“改” | `RuneScheme.isModified` 判断真实外环增强 | 保留普通卷轴语义；只解释通用符文效果/代价，不导入法术解法 |
| 白名单虚构命令 | 当前命令树没有 `whitelist add/remove/list/clear` | 改为 `my_whitelist` GUI，注明服务端开关、名单空/非空和友方判定 |

## 知识覆盖

全库共 2,251 个分版本条目，运行时只检索当前安装组合。SSC 两版各32个形态；1.9.2/1.10.0 分别411/406个关联能力、79/109个物品/方块/效果条目和42/69个配方。SSCA 两分支各23个形态、26个法术、99个物品/方块/效果、44个配方、11个双道具进化起点；关联能力分别280/256个。

固定快照不代表服务器已启用全部条目。能力型配方还取决于当前形态挂载，数据包和配置可以改变默认值。详细 Wiki 的基线是 SSC 1.10.0，不能被用于证明 1.9.2 的数值。未知发行版本只返回适用的通用条目，不静默借用另一版细节。

`generated/manifest.json` 记录源 commit、发行 JAR SHA-256 和每个读取输入的 SHA-256。刷新脚本支持只比较不写入的 `--check`。普通 Gradle 构建不访问网络、不需要相邻模组或 Wiki 仓库。

## 验证与剩余验收

- `clean check build` 及最终 `check build`：Java 17 离线完整构建成功，218项回归通过；覆盖旧/新读取路径、连续切换形态、空同步状态、异常传播、非公开组件键、两套环境的实际知识检索、形态别名、叙事过滤和打包内容。
- `tools/check_ssc_api.py`：直接读取真实发行 JAR 的 class 文件，28项接口签名检查通过，验证反射名称与参数。它不启动 Minecraft，也不是完整游戏集成测试。
- 仍需游戏内确认：在 SSC 1.9.2 和 1.10.x 各进入世界，查询当前形态；切到原版、SSCA和人类形态后再次查询；重连后查询；检查法力、冷却和版本对应命令回答。未安装 SSC 的环境应清楚提示未安装。
- 本轮没有调用真实 AI API，也没有验证实际多人同步、画面或真实游戏交互。
